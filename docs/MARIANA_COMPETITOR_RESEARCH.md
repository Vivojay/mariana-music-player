## EQUALS capability inventory

The acceptance column defines what it would take to call a capability complete. EQUALS includes social functions alongside player integrations. Obtaining an album's metadata, following its artist, publishing a review and playing its recording are four separate operations.

| EQUALS behavior | Mariana implementation path | Acceptance and remaining work |
| --- | --- | --- |
| Fan profile with username, biography, favorites and collection | Personal profile and portable collection | Local display and a validated file exchange can ship offline. Discoverable usernames, account ownership and profile deletion require a service. |
| Track and album collections, personalized digital record wall | Save both media types with artist/title identity and show them in a collection | Portable snapshots convey actual user selections. A public grid, custom cover designs, trophies and share-card images each need their own acceptance. |
| Artist-tagged or untagged opinions, track/album reviews, ratings | Persist original reviews and ratings separately from editorial reports | Verify edit/delete, literal user text, artist matching, duplicate imports and offline reload. Public aggregates need distinct accounts and abuse handling. |
| Real-time listening feed and tastemakers | Local chronological feed, explicit snapshot import, optional following | An imported snapshot has an observation date. Continuous friend activity requires consented presence, expiry, updates and revocation. |
| Taste matches with percentage, shared artists and friend discovery | Compute an explainable overlap within the imported profiles | Show the denominator and empty samples. Discovery of strangers needs an opt-in searchable account graph and visibility controls. |
| Breaking music news, trending moments and emerging performers | Distinguish recent releases, dated editorial items and official destinations | Confirm identity, attribution, timestamps and deduplication. Trending requires a defined population, time window and observations. An article link alone cannot establish a trend. |
| Artist fan communities, group chat, DMs and sharing tracks | The optional Matrix client accesses rooms on a user-selected homeserver. [Room commands and verification](FAN_ROOMS.md) | Two users should be able to join, post, receive, leave, block and report. Private chats, live delivery, push, encrypted rooms and authorization deserve separate acceptance. |
| Polls, discussion threads, reactions and concert conversations | Matrix replies, threads, reactions and disclosed single-choice polls reference their original events. The terminal client can create, vote, tally and close these polls. Encrypted and multi-select poll support remains open. | Aggregate one eligible vote per person, handle edits and withdrawn events, verify thread ordering, source attribution and offline recovery. |
| Artist trivia/quiz cards, tournament quiz, fan badges and rank | Local factual questions and earned progress | Preserve score through a restart and identify question provenance. Competitive standing requires scoring on a trusted service, an event window and moderation. |
| Artist, album, track and recent-listen statistics, shareable history stories | Reuse optional local playback history | Exclude private activity from exports unless intentionally shared. Cross-service totals need identity reconciliation and clear time units. |
| Custom chat backgrounds, colored text, streaks and view counts | Theme the client and define each counter independently | Accessible custom colors and local achievements stand alone. Cross-user streaks and view counts need actual events, visibility rules and duplicate suppression. |
| Track-bearing messages, direct-message moderation, profile phone number, mobile sign-in | Add optional accounts with per-surface preferences and moderation | Verify member access, block/report handling, graceful account deletion and private phone-number defaults on the actual service. |
| Spotify/Apple Music account connection | Separate consented provider adapters and disconnect/revoke | Use permitted SDKs and provider credentials. Gate playback by subscription and policy. Keep authorization, listening history import and audio playback separately testable. |
| Paid tiers and consumable credits | Possible future entitlement service | Test purchase, restore, renewal, refund, expiration, region change and a reconciled credit ledger before offering products. The public material supplies no complete benefit-to-tier map. |

## Player, surfaces and release criteria

- **Sound design.** Audacity's tone/chirp tools expose waveform, duration, frequency and sweep endpoints. For Mariana, verify frequency against generated PCM, endpoint accuracy, short fades, level bounds and command cancellation. Audacity's editor and Mariana's player have separate transport requirements. [Tone](https://manual.audacityteam.org/man/tone.html) · [Generator reference](https://manual.audacityteam.org/man/index_of_effects_generators_and_analyzers.html)
- **Themes and navigation.** Webamp demonstrates the reach of a coherent Winamp-style player in a browser. Dracula provides a documented palette; cmus demonstrates keyboard-first views, configuration and terminal colors. Mariana can give named color roles stable meanings across renderer and terminal, with reduced motion and legible focus states. Implement original artwork for Flow and keep normal mode navigable without a pointer. [Webamp](https://github.com/captbaritone/webamp) · [Dracula palette](https://draculatheme.com/contribute) · [cmus manual](https://github.com/cmus/cmus/blob/master/Doc/cmus.txt)
- **Mobile and watches.** A tested browser app, phone package, phone media controls on a watch, and independently installable watch app are distinct deliverables. Test interruptions, audio routing, locked-screen behavior, background resume and offline persistence per target. Apple provides independent watchOS apps and Now Playing controls; Wear OS has distinct media and distribution guidance. [watchOS](https://developer.apple.com/documentation/watchos-apps/creating-independent-watchos-apps/) · [Apple Now Playing](https://developer.apple.com/documentation/nowplaying) · [Wear OS audio](https://developer.android.com/training/wearables/apps/audio) · [Wear distribution](https://developer.android.com/training/wearables/packaging)
- **Public social release.** Before operating public accounts, demonstrate two-user delivery, access isolation, visibility controls, report/block, moderation turnaround and clean deletion across clients. Play's UGC policy and Apple's review guidelines describe moderation expectations. A Matrix client can reuse a chosen homeserver's membership and messaging, while Mariana remains responsible for its own UI and store submission. [Matrix client protocol](https://spec.matrix.org/latest/client-server-api/) · [Google Play UGC](https://support.google.com/googleplay/android-developer/answer/9876937) · [Apple review guidelines](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)
- **Service access.** Spotify playback and Apple Music personal data require their own approved integrations; a link to a song does not convey an account entitlement. Provider/editorial directory rows should distinguish a homepage, archive, verified feed and playable stream; chronological releases should separately identify future announcements and already observed releases. [Spotify policy](https://developer.spotify.com/policy) · [MusicKit](https://developer.apple.com/musickit/) · [MusicBrainz request guidance](https://musicbrainz.org/doc/MusicBrainz_API)
